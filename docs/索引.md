# 代码与数据格式索引

给"要改这个项目的人 / AI"用的。**改代码前先在这里定位函数，再动手。**
行号会随改动漂移，用函数名搜（`grep -n "function 名字" src/mc-backup.js`）。

## 1. 文件一览

| 文件 | 行数级别 | 作用 |
| --- | --- | --- |
| `src/mc-backup.js` | ~1600 | 引擎全部逻辑 + `install` 一键安装；命令行入口在文件末尾的 `case` 分支 |
| `web/card-backup.html` | ~1050 | 面板卡片：读状态、画界面、往队列写请求（纯 HTML+JS，无依赖） |
| `tests/sandbox-test.js` | ~700 | 全功能沙盒：假 GTNH 服务端 + 真实引擎，跑完所有面板请求 |
| `tests/chain-test.js` | ~120 | 手动档 / 自动档两条链、保留策略、manualKeep 上限 |
| `tests/card-test.js` | ~300 | 用假 DOM 跑卡片脚本（进度条、下拉、设置、收起/展开） |
| `tests/retention-test.js` | ~150 | 时间段锚点新算法 vs 旧算法对比 |

命令行用法（`src/mc-backup.js` 末尾的 switch）：

```
node mc-backup.js install [--yes] [--service] [--name 名字] [--daemon-data 目录] [--runtime-dir 目录]
node mc-backup.js status                      # 刷新状态文件（卡片读它）
node mc-backup.js snapshot [-i 实例名]        # 立刻给实例存一份（算自动档）
node mc-backup.js queue                       # 处理一轮面板请求
node mc-backup.js watch                       # 常驻：5 秒扫队列 + 按整刻自动存档 + 60 秒刷状态
node mc-backup.js prune                       # 按保留策略清一次
node mc-backup.js list                        # 列出各实例快照
```

## 2. 引擎函数索引（`src/mc-backup.js`）

### 基础工具

| 函数 | 作用 |
| --- | --- |
| `log(msg, level)` | 控制台 + 同目录 `mc-backup.log` 双写 |
| `readJson` / `writeJson` | 读 / 写 JSON；**写入固定 UTF-8 无 BOM**（卡片 fetch 要求） |
| `exists` / `stat` / `mkdirp` / `rmrf` | 文件系统小工具 |
| `b64uDecode` / `b64uEncode` | 队列文件名用的 base64url（避免中文顶到 Windows 路径上限） |
| `mb(bytes)` | 字节 → MB（1 位小数） |
| `copyTree` / `countFiles` / `copyTreeProgress` | 目录复制；后者带进度（回档/导出用） |

### 配置与实例

| 函数 | 作用 |
| --- | --- |
| `migrateTiers(tiers)` | 老配置升级：档位缺 `full` 字段时补上 |
| `backupRoot` / `queueRoot` / `statusFile` / `instBackupDir` | 各种路径推导 |
| `saveConfig()` | 配置写回 |
| `instInterval` / `instTiers` / `instFullKeep` / `instManualKeep` | 实例生效的设置（实例自己的优先，否则全局） |
| `minInterval()` | 所有实例里最小的存档间隔（调度用） |
| `alignedMark(ms, stepMs)` | **把时刻对齐到系统整刻**（10 分钟 → 12:00/12:10…） |
| `instNextSaveAt(inst)` | 该实例下一次自动存档时间 |
| `instInclude(inst)` | 生效的备份内容清单（按实例目录真实大小写还原，GTNH 的 `World` 大写） |

### 面板 / 节点通信

| 函数 | 作用 |
| --- | --- |
| `panelLogin()` | 用配置里的账号密码登录面板，拿 token（带 session cookie） |
| `panelCall(apiPath, method)` | 带 token 调面板 API |
| `instStatus` / `instStop` / `instStart` / `instCommand` | 查状态 / 停 / 开 / 发指令（回档前停服、回档后开服） |

### 快照

| 函数 | 作用 |
| --- | --- |
| `snapshotList(inst)` | 读备份目录里所有快照的 meta（返回含 `manual` / `baseName`） |
| `dirSize(dir)` | 目录实际占用 |
| `complete(s)` | 这份快照能不能独立回档（`full` / `hardlink` 都算能） |
| `targetSnapshot(inst, which)` | 按名字或 `latest` 找到目标快照（找不到就报错） |
| `scanTree(inst)` | 扫实例目录，列出要备份的文件（按 `include` / `excludeFileNames` 过滤） |
| `newSnapshot(inst, forceFull, manual)` | **核心**：建/刷新一份快照。`manual && !forceFull`（立刻保存）→ 转到 `refreshSnapshot()` 刷新最近那份手动档；`forceFull`（全部保存）→ 新建一份完整复制；都没有时新建一份（基准取最新的那份，**不会白抄完整复制**）。先写 `.tmp` 再改名，半成品不会被当成有效快照；复制后对齐 mtime |
| `refreshSnapshot(inst, base)` | **「立刻保存」的实际动作**：遍历当前实例文件 —— 快照里没有的/变了的不动就复制进去（并对齐 mtime），没变的保持，源里已删除的从快照里删掉；随后更新 `meta`（`refreshedAt` / `refreshCount` / 文件数 / 本次写入量）并跑一次 `prune` |
| `scanTreeIn(rootDir, inst)` / `scanTree(inst)` | 用同一套 `include` / `excludeFileNames` 规则扫目录（后者等价于扫实例目录；前者也用来扫快照目录，判断哪些文件该删） |

### 区块级（`.mca` 原始读写，不解压）

| 函数 | 作用 |
| --- | --- |
| `mcaReadChunk(file, cx, cz)` | 从区域文件里读出某个区块的原始数据（4 字节长度 + 压缩数据） |
| `mcaWriteChunk(file, cx, cz, payload)` | 写回某个区块：原位置放得下就原地覆盖，否则追加扇区并更新位置表 / 时间戳 |
| `chunkCoords(blockX, blockZ)` | 方块坐标 → 区块 / 区域坐标（1 区块=16×16 方块，1 区域=32×32 区块） |
| `regionRel(world, rx, rz)` / `relJoin` | 拼 `world/region/r.x.z.mca` 路径 |
| `chunkHistory(inst, world, blockX, blockZ)` | 该区块在各快照里的变化历史（只列变化点，带 md5 前 8 位） |
| `writeChunkHistory(inst, h)` | 写 `mcchunk-history-<uuid>.json` 给卡片读 |
| `restoreChunk` / `restoreRegion` | 只回档一个区块 / 整个区域文件（回档前先备份原文件） |

### 保留策略（最核心、最容易改错）

| 函数 | 作用 |
| --- | --- |
| `timeBlock(dateMs, minutes)` | 把一个时刻归到"自然时间段"（以本地 0 点为基准切块） |
| `tierName(minutes)` | 档位显示名（60 → "1 小时档"） |
| `planRetention(desc, tiers, base)` | **增量档**计划：最小档按最新 N 份；粗档每个自然时间段钉一份（取该段最早那份） |
| `planFullKeep(fullsDesc, tiers)` | **完整档**计划：每档按 `full` 份数留；粗档锚点必须来自"更早且还没被占用"的时间段 |
| `retentionPlan` / `retentionPlanAll` | 汇总：自动增量 + 自动完整 + 手动档（按 `manualKeep`）；**自动档里最新那份一定留**（兜底） |
| `prune(inst)` | 按上面的计划真删文件，并写日志（含各档锚点） |

### 回档 / 导出

| 函数 | 作用 |
| --- | --- |
| `withInstanceStopped(inst, body, noStart)` | 回档前停服（最多等 120 秒）→ 执行 → 自动开服 |
| `filesBackup(inst, rel)` | 动手前把将被覆盖的文件另存到 `_manual/<时间戳>/` |
| `worldList(snapDir, inst)` | 快照里的世界列表（含 region 数、大小、类型标注） |
| `worldKind(rel, dir)` | 世界类型：主世界 / 下界 / 末地 / 个人维度 `DIM-xxx` / 平坦 / 虚空（**目录名大小写不敏感**） |
| `playerList` / `playerNameMap` / `playerRelFiles` / `playerBaseOf` / `playerFilesOf` | 玩家存档：uuid 与 GTNH 的 `players/名字.dat` 两种；`playerBaseOf` 按**实际位置**判断在 playerdata 还是 players |
| `restoreWorld` / `restorePlayer` / `transferPlayer` / `restoreAll` | 世界回档 / 玩家回档 / 玩家数据转移 / 整包回档 |
| `exportInstance(inst, snap, opt)` | 导出整份存档 / 世界 / 玩家（可带/不带/只带某玩家数据） |
| `exportServer(inst, clean)` | 导出整个服务端；`clean=true` 为纯净服务端（去存档、玩家名单、logs） |

### 进度 / 状态 / 设置 / 队列

| 函数 | 作用 |
| --- | --- |
| `beginTask` / `stepTask` / `endTask` / `writeProgress` | 进度文件（卡片进度条读它）；心跳 `setInterval` 与完成态 `setTimeout` 都 `.unref()`，命令行跑完立刻退出 |
| `writeStatus()` | 写 `mcbackup-status.json`（卡片唯一数据来源，含 `nextSaveAt` / `serverTime` / 每个快照的 `tier` / `manual`） |
| `countRequests(root)` | 数队列里还有几个待处理请求 |
| `setInclude(listText, target)` | 改备份内容（支持分片提交） |
| `applySettings(jsonText)` | 面板"保存设置"：全局或单个实例的间隔 / 档位 / 完整份数 / 手动份数 / 路径 |

## 3. 队列请求格式（卡片 → 引擎）

请求就是队列目录里的一个**空文件**，文件名 = 命令。带参数时文字部分用 **base64url**（`b64u()`），参数之间用 `~` 分隔：

```
snapshot.req                                    立刻保存（增量，标记为手动档）
snapshot-full.req                               全部保存（完整复制，标记为手动档）
restore-latest.req                              整包回档到最新
restore-<快照名>.req                             整包回档到指定快照
restoreworld-<b64世界>~<快照|latest>.req          世界回档
restoreplayer-<b64世界>~<b64玩家key>~<快照>.req    玩家回档
xferplayer-<b64世界>~<b64源>~<b64目标>~<live|快照>.req   玩家数据转移
restorechunk-<b64世界>~<方块X>~<方块Z>~<快照>.req   只回档一个区块
restoreregion-<b64世界>~<方块X>~<方块Z>~<快照>.req  回档整个区域文件
findchunk-<b64世界>~<方块X>~<方块Z>.req            查区块历史（写 mcchunk-history-<uuid>.json）
exportsave-<快照>~<all|none>~<b64玩家?>.req        导出整份存档
exportworld-<b64世界>~<快照>~<all|none>.req        导出单个世界
exportplayer-<b64世界>~<b64玩家>~<快照>.req        导出单个玩家
exportserver.req  /  exportserver-clean.req      导出整个服务端 / 纯净服务端
delsnap-<快照名>.req                             删除某份快照
note-<b64世界>~<b64备注>.req                     世界备注（备注空 = 清除）
settings-<b64(JSON)>.req                         改设置；JSON 形如 {"d":"实例uuid或省略","b":间隔分钟,"t":[[分钟,增量份,完整份],…],"r":存档路径,"e":导出路径}（老卡片还带 "f":完整份数） |
setinclude-<b64内容>.req                         改备份内容
setinc-<global|uuid>~<片号>~<总片数>~<b64分片>.req 备份内容分片提交（内容太长时用）
enable.req / disable.req                        开启 / 停用该实例的备份
```

> 文件名里有中文会超 Windows 260 路径上限（实测 258 能建、260 静默失败），所以**一律 base64url**。

## 4. 数据格式

### 4.1 快照目录

```
<backupRoot>/<实例名>/<YYYYMMDD-HHMMSS>_<full|hardlink|inc>/
    World/…  config/…            ← 备份内容（按 include 清单）
    meta.json                    ← 元信息
```

`meta.json`：

| 字段 | 说明 |
| --- | --- |
| `name` | 快照名（时间戳 + 类型） |
| `type` / `format` | `full`（完整复制）/ `hardlink`（增量，未变文件用硬链接）/ `inc`（老格式增量链） |
| `manual` | **true = 面板上手动点出来的**（不进自动保存循环、不参与自动时间段轮转） |
| `baseName` | 这次增量是拿哪一份当基准算的（手动链只看手动档） |
| `createdAt` | ISO 时间 |
| `files` / `fileCount` | 文件数 |
| `treeMB` | 快照总大小 |
| `sizeMB` / `deltaMB` | 本次实际新写入的 MB |
| `copied` / `linked` / `linkFail` | 新复制 / 硬链接复用 / 硬链接失败的数量 |
| `seconds` | 本次耗时 |
| `parent` | 只有老格式 `inc` 链才用（回档要连带父快照） |
| `source` / `instanceUuid` | 来源实例 |

### 4.2 状态文件 `mcbackup-status.json`（卡片读它）

```jsonc
{
  "generatedAt": "2026-09-22 12:52:00",        // 状态生成时间
  "serverTime":  "2026-09-22 12:52:00",        // 系统时间（卡片右上角另有一个每秒走的本地钟）
  "pending": 0,                                 // 待处理请求数
  "daemonId": "…", "backupRoot": "…", "queueRoot": "…", "exportRoot": "…",
  "include": [ … ],                             // 全局备份内容
  "settings": { "baseMinutes": 10, "fullKeep": 0, "manualKeep": 20,
                "tiers": [{ "minutes": 10, "keep": 6, "full": 0 }, …] },
  "instances": [{
    "uuid": "…", "name": "mc-1", "enabled": true,
    "count": 8, "fulls": 1, "incs": 7, "latest": "…", "latestTime": "09-22 12:51:59",
    "totalMB": 279.9, "lastSeconds": 0.5, "lastFiles": 2090, "lastCopied": 0,
    "interval": 10, "nextSaveAt": "13:00:00",   // 下一次自动存档（对齐系统整刻）
    "manualCount": 2, "manualKeep": 20,
    "tiers": [ … ], "include": [ … ],
    "snapshots": [{ "name": "…", "type": "hardlink", "manual": false,
                    "tier": 60, "tiers": [60], "time": "09-22 11:01:49", "sizeMB": 12, "deltaMB": 0.2 }, …],
    "worlds":  [{ "world": "World", "kind": "主世界", "regions": 70, "sizeMB": 172.2, "note": "玩家A的主世界", "snaps": [ … ] }, …],
    "players": [{ "world": "World", "key": "uuid或名字", "uuid": "…", "name": "…", "legacy": false,
                  "sizeKB": 12.3, "stats": true, "adv": true, "mainRel": "playerdata/xxx.dat" }, …]
  }]
}
```

### 4.3 进度文件 `mcbackup-progress.json`（卡片进度条读它）

```jsonc
{ "task": "snapshot|restore|export|done|idle", "instance": "mc-1",
  "total": 2090, "done": 1240, "percent": 59, "seconds": 3.2,
  "startedAt": "…", "updatedAt": "…", "message": "已处理 1240/2090 个文件" }
```

`task=done` = 刚做完（卡片画绿色满格条，引擎 90 秒后清成 `idle`）。

### 4.4 区块历史 `mcchunk-history-<uuid>.json`

```jsonc
{ "generatedAt": "…", "instanceUuid": "…", "world": "World",
  "blockX": 100, "blockZ": 200, "chunkX": 6, "chunkZ": 12,
  "regionFile": "World/region/r.0.0.mca", "snapshotCount": 10,
  "rows": [{ "name": "快照名", "time": "09-22 11:01:49", "exists": true, "size": 12345, "hash": "6aa16221" }] }
```

## 6. 常见改动怎么做

| 想改什么 | 改哪里 | 别忘了 |
| --- | --- | --- |
| 加一种"面板能点的操作" | ① 卡片 `submit('xxx-….req')` ② 引擎 `processQueue()` 里加 `else if (req.startsWith('xxx-'))` 分支 ③ `tests/sandbox-test.js` 加对应断言 | 请求名里的中文要 base64url |
| 改保留策略 | 引擎 `planRetention` / `planFullKeep` / `retentionPlanAll` | 跑 `tests/chain-test.js` + `tests/retention-test.js`；注意"手动档不参与自动轮转"和"自动档最新那份兜底"两条不能破坏 |
| 加/改设置项 | 引擎 `parseTiers` / `applySettings` / `writeStatus` 的 `settings`；卡片 `renderSettings` / `saveSettings` / `readTiers` | 老的请求字段要兼容（见 `applySettings` 里的 `s.f`） |
| 改界面布局/文案 | 卡片 HTML 与 `render*` 函数 | **必须顶 `?v=`**（见 `AGENTS.md` 第 3 条） |
| 加快照里的内容 | `include` 默认值（引擎里 install 模板 + 配置文件） | GTNH 的 `World` 大写、`players/名字.dat`、个人维度 `DIM-xxx` 要照顾到 |
| 加测试 | 在 `tests/` 里仿照现有脚本（都用 `MC_BACKUP_ENGINE` / `MC_BACKUP_CARD` / `MC_BACKUP_TMP` 环境变量定位文件与临时目录） | 保证 Linux 上也能跑（CI 会跑） |
